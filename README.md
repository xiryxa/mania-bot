# MANIA Bot

Telegram-бот для бренда охотничьих товаров **MANIA** — автоматизация продаж манков, засидок и аксессуаров.

---

## Возможности

- 🛒 **Каталог товаров** с пагинацией и фото, разбит по категориям
- 📦 **Оформление заказа** с выбором способа доставки (Почта России, СДЭК, Яндекс Доставка)
- 👤 **Личный кабинет**: регистрация, редактирование профиля, история заказов с фильтрами
- 🔐 **Админ-панель**: управление заказами, товарами, экспорт заказов в CSV
- 📢 **Массовая рассылка** от админа с предпросмотром и подтверждением
- 🔄 **Автоматический пересчёт остатков** при отмене и возврате заказа в работу
- ⚠️ **Уведомления о низком остатке** товара администраторам
- 📊 **Отслеживание заказов**: трек-номера, подтверждение получения

---

## Стек

- Python 3.11+
- [Aiogram 3](https://docs.aiogram.dev/) — асинхронный фреймворк для Telegram Bot API
- SQLite + [aiosqlite](https://github.com/omnilib/aiosqlite) — асинхронная работа с БД
- FSM (Finite State Machine) — пошаговые сценарии регистрации, заказа, рассылки
- [python-dotenv](https://github.com/theskumar/python-dotenv) — переменные окружения из `.env`
- [pytz](https://pythonhosted.org/pytz/) — конвертация времени в московское
- [email-validator](https://github.com/JoshData/python-email-validator) — валидация email

## Установка и запуск (локально)

### 1. Клонировать репозиторий

```bash
git clone https://github.com/xiryxa/mania-bot.git
cd mania-bot
```

### 2. Создать и активировать виртуальное окружение

```bash
python -m venv .venv
```

**Windows:**
```bash
.venv\Scripts\activate
```

**Linux / macOS:**
```bash
source .venv/bin/activate
```

### 3. Установить зависимости

```bash
pip install -r requirements.txt
```

### 4. Настроить переменные окружения

Скопируй `.env.example` в `.env`:

```bash
cp .env.example .env
```

Открой `.env` и заполни:

| Переменная | Что это |
|------------|---------|
| `BOT_TOKEN` | Токен бота от [@BotFather](https://t.me/BotFather) |
| `ADMIN_IDS` | Список Telegram ID администраторов через запятую |
| `ADMIN_USERNAMES` | Список юзернеймов администраторов через запятую (в том же порядке, что `ADMIN_IDS`) |

Свой Telegram ID можно узнать у бота [@userinfobot](https://t.me/userinfobot).

### 5. Запустить бота

```bash
python main.py
```

Если всё настроено верно, в логах появится:
```
INFO:__main__:🤖 Бот запущен! Нажмите Ctrl+C для остановки.
INFO:aiogram.dispatcher:Run polling for bot @...
```

База данных `users.sqlite` создастся автоматически при первом запуске.

    ├── router.py              # Команды /start, /command, /register, /profile
    ├── navigation.py          # Навигация: /about, переходы по разделам

## Архитектура

### Порядок регистрации роутеров

Роутеры подключаются в `main.py` в следующем порядке:

```
admin → admin_broadcast → user → navigation → profile → profile_orders
      → orders → products → shop → fallback
```

Порядок важен: Aiogram обрабатывает апдейты **сверху вниз**, первый подходящий роутер выигрывает. Специфичные роутеры (`admin`, `orders`) идут раньше общих, `fallback` — последним.

### Разделение по доменам

Каждый модуль в `handlers/` отвечает за свой домен:

- **`router.py`** — только команды пользователя (регистрация, профиль, магазин).
- **`navigation.py`** — статические разделы (About, Help).
- **`profile.py`** — редактирование профиля и FSM регистрации.
- **`profile_orders.py`** — просмотр своих заказов, пагинация, подтверждение получения.
- **`orders.py`** — создание заказа (FSM-цепочка от выбора товара до сохранения).
- **`admin*.py`** — всё, что доступно только админам.

Такое разделение упрощает навигацию по коду: если баг в истории заказов — открываем `profile_orders.py`, а не ищем по 1500-строчному файлу.

## Ключевые технические решения

### Атомарное списание остатков

В `db.py` функции `decrease_product_stock` и `create_order_and_decrease_stock` используют **условный `UPDATE`**:

```sql
UPDATE products
SET quantity = quantity - ?
WHERE id = ? AND quantity >= ?
```

Проверка остатка встроена в само условие `UPDATE` — а не сделана отдельным `SELECT` перед ним. Это устраняет race condition: даже при двух одновременных заказах остаток не уйдёт в минус.

### Кэширование `ADMIN_IDS`

В `filters.py` список `ADMIN_IDS` читается из `.env` **один раз при импорте модуля**, а не при каждом апдейте. Это микрооптимизация, но она убирает лишний парсинг на горячем пути.

⚠️ **Особенность:** если изменить `ADMIN_IDS` в `.env`, потребуется перезапуск бота. Для продакшена это норма — админы не меняются ежедневно.

### Пагинация фото через `edit_message_media`

Во всех местах, где есть список с фото (каталог, заказы, товары), используется `edit_message_media` вместо `delete_message` + `answer_photo`. Это убирает мигание интерфейса и снижает нагрузку на Telegram API при быстром пролистывании.

Для случая «фото → текст» (когда у товара нет картинки) сначала удаляется фото-сообщение, а потом отправляется новое текстовое — без попытки редактировать удалённое сообщение.

### Отложенный импорт для разрыва циклов

В некоторых модулях (`main.py`, `admin.py`) используется **локальный импорт** внутри функции — например, `from handlers.admin import ADMIN_IDS` внутри `db.notify_user_safe`. Это разрывает циклические зависимости между модулями.

## Разработка

### Рабочий процесс

Проект разрабатывается небольшой командой с привлечением AI-ассистентов:

- **Ревью кода** — Claude (раз в день, архитектурные замечания).
- **Парное программирование** — DeepSeek (написание кода, поиск багов).
- **Трекинг прогресса** — Gemini (обзор статуса).

Это не формальность: за время работы такой схемы найдены и закрыты критичные баги (race condition в списании остатков, потеря `user_id` при пропуске комментария к заказу), сделан рефакторинг монолитных модулей.

### Работа с базой данных

**Важно:** вся работа с БД сосредоточена в `db.py`. Хэндлеры не обращаются к `aiosqlite` напрямую — они вызывают функции из `db`. Это упрощает миграции и тестирование.

### Форматирование

- Python-код — стандартный PEP 8.
- Файлы заканчиваются переводом строки (для совместимости с git-хуками).
- Русские комментарии допустимы, но код — на английском.

## Деплой на VPS (Ubuntu 24/7)

### Текущее состояние

⚠️ **Известное ограничение:** сейчас бот запускается вручную через `python main.py` в терминале. При падении процесса или перезагрузке сервера — не поднимается автоматически.

Перед реальным деплоем на VPS нужно настроить автозапуск через **systemd**.

### Рекомендуемый план деплоя (TODO)

1. **Подготовить VPS:** Ubuntu 22.04+, Python 3.11+.
2. **Скопировать проект** на сервер (git clone или rsync).
3. **Создать venv**, установить зависимости.
4. **Настроить `.env`** с реальными боевыми значениями.
5. **Создать systemd-юнит** `/etc/systemd/system/mania-bot.service`:
   - `WorkingDirectory` — папка проекта
   - `ExecStart` — путь к venv python + `main.py`
   - `Restart=always` — автоперезапуск при падении
   - `User` — не root, а отдельный системный пользователь
6. **Включить и запустить сервис:** `systemctl enable mania-bot && systemctl start mania-bot`.
7. **Настроить логирование** в файл (сейчас только stdout).
8. **Настроить бэкап** `users.sqlite` (cron + rsync / файловая копия).

Подробная инструкция будет добавлена в этот раздел перед деплоем.

## Известные ограничения и технический долг

- **`sqlite3.Row`** — часть функций в `db.py` возвращает кортежи, и код обращается к ним по индексам (`order[1]`, `product[5]`). Это работает, но хрупко: при изменении схемы таблицы легко ошибиться. В планах — постепенный перевод на доступ по именам колонок.
- **Миграции вручную.** Схема БД обновляется через `PRAGMA table_info` + `ALTER TABLE` в `init_db()`. Для проекта такого масштаба этого достаточно, но при росте данных стоит задуматься о версионировании миграций.
- **Нет автотестов.** Тестирование проводится вручную через Telegram. В планах — добавить `pytest` хотя бы на критичные функции (создание заказа, списание остатков).
- **Логирование в stdout.** При деплое на VPS нужно настроить запись в файл с ротацией.
